# قاعدة البيانات — المرحلة الأولى

الملف: `supabase/migrations/20261018100000_phase1_core.sql`

## القرارات المعمارية

- **جدول `organizations` واحد لكل أنواع الأنشطة** (`gym`, `independent_coach`, `sports_facility`, `store`). السبب: الصفحة العامة، البحث، الموقع، الساعات، الصور، التقييمات والصلاحيات متطابقة بين الأنواع. التفاصيل الخاصة بالنوع (منتجات المتاجر، برامج المدربين لاحقاً) في جداول مرتبطة.
- **العزل بين الأنشطة:** كل جدول فرعي يحمل `organization_id`، وسياسات RLS تعتمد على `is_org_member()`. أي تعديل لـ `organization_id` مرفوض أو يُتجاهل بـ trigger.
- **الصلاحيات الحساسة بـ triggers:** غير الأدمن لا يستطيع نشر نشاط، أو توثيقه، أو تغيير نوعه، أو اعتماد منتج. الأدمن = وجود المستخدم في `platform_admins` (جدول بلا سياسات).
- **الكتابة من الخادم فقط** لـ `inquiries` و`analytics_events` و`audit_logs` (يحتاجون rate limiting ومنع تكرار). لا توجد سياسة INSERT لهم للمتصفح؛ الخادم يستعمل service role ولا يظهر مفتاحه للمتصفح أبداً.
- **تقييمات:** مستخدم واحد لكل نشاط، لا يقيّم نشاطه، الهوية تُؤخذ من الجلسة، ولا يستطيع تغيير حالة التقييم. النشاط لا يحذف التقييمات، فقط يرد أو يبلغ.
- **المكملات الغذائية:** أي منتج بفئة `requires_review` يبدأ `pending` ويعود `pending` عند تعديل الاسم/الوصف/المكونات/القيم الغذائية، ولا يظهر للعامة إلا بعد اعتماد الأدمن.
- **التسعير والتوفر:** `price_updated_at` و`availability_updated_at` تتحدثان تلقائياً عند التغيير فقط، لعرض "آخر تحديث" بصدق.

## مصفوفة الصلاحيات (ملخص)

| الجدول | العامة | أعضاء النشاط | مالك/مدير |

| organizations | المنشور فقط | نشاطاتهم | تعديل (بدون نشر) |

| products / offers | المنشور والمعتمد / ضمن المدة | قراءة وكتابة (كل الأعضاء) | — |

| reviews | المنشور | — | رد فقط |
| analytics | لا | قراءة نشاطهم | — |

## الاختبارات

```bash
npm run test:db
```

تشغّل المخطط على Postgres محلي (PGlite) مع بدائل بسيطة لـ `auth` و`storage` (`supabase/tests/stubs.sql`)، وتتحقق من العزل بين الحسابات، حماية الأعمدة الحساسة، التقييمات، الاستفسارات، العروض، رفع الصور، والحذف المتسلسل. هذه الاختبارات لا تغني عن فحص `get_advisors` على Supabase الحقيقي بعد تطبيق الـmigration.

## ما ليس هنا بعد

المجتمع، JordanGym Coach، واتساب API، الاشتراكات والدفع، الإعلانات المدفوعة، حسابات المنشآت المتقدمة، وبيانات تجريبية. كلها مراحل لاحقة.

## تنبيهات Supabase Advisors المقبولة عمداً

- `platform_admins` بلا سياسات: مقصود، الجدول غير قابل للقراءة من المتصفح.
- `is_org_member`, `is_platform_admin`, `org_is_published` قابلة للتنفيذ من `anon`/`authenticated`: سياسات RLS تستدعيها بصلاحية المستخدم، وهي ترجع true/false فقط عن عضوية المستخدم نفسه أو عن حالة نشاط منشور أصلاً. دوال الـtriggers سُحب منها EXECUTE (migration `hardening`).
- تنبيهات "multiple permissive policies" ناتجة عن سياسة الأدمن بجانب سياسات الأعضاء. لا أثر يُذكر بحجم البيانات الحالي؛ نعيد النظر بعد وجود حركة فعلية.
